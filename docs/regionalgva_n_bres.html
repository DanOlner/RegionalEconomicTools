Regional GVA and job count data: easy squeezy versions

What’s this?

  • Easy-access ONS regional GVA by SIC sector data: ITL2 & 3 geographies, SIC 2-digit, Section and Production/Construction/Services, 1998 to latest
  • Same for BRES (the Business Register and Employment Survey) region-by-sector job count data, with extra-bonus higher accuracy values. 2015 to latest.
  • Those two linked together into single GVA/jobcount datasets (so 2015 to latest)

Why?

  • The ONS publish regional GVA data for the UK, covering a range of SIC sectors (2022 is the latest available year at time of writing - the data’s here). But it’s a faff to extract data from the excel sheets, especially for use in R or similar.
  • This page provides easy-to-access copies from that dataset, with each useful dataset in its own CSV. It’ll be updated when the latest GVA data comes out.
  • This data also feeds into other tools/code on this website like sector analysis, GVA gap analysis. (See left-hand bar.)

Also:

  • UK regional/sectoral job count data is available via BRES (the Business Register and Employment Survey) on NOMIS, but again not in the most easily-useable form. (E.g. the website’s query form will separate out different fields into their own chunk in the file.)
  • It’s also possible to extract more accurate job count numbers by aggregating up from the most granular sector counts (see the related blog post for more on this.) The BRES data below uses these more accurate counts.
  • So there’s also quick-access versions of all the most useful versions of the latest BRES data, including previously available years.

Also also:

  • It’s useful to have both regional GVA and job count values combined (for e.g. GVA per job analysis, or to have gva and job analysis using the same SIC categories and places) - this page also has linked GVA and job count data.
  • There are several wrinkles with this data to get them to play nicely together that anyone using should be aware of - see details below.
  • Or for even more horrific detail, see this blog post on what the code’s doing and what data shaping choices have gone into the GVA / BRES join. Any thoughts on things I’ve stuffed up or that could be improved, let me know in the github issues.
  • The blog post also explains details you may need if new to this data, like the difference between Current Prices and Chained Volume prices (and why each has to be treated very differently in analysis e.g. don’t sum chained volume…)

Automate!

Every step - from downloading the data to creating the link tables below - is automated.

Making data processing like this as automated and repeatable as possible makes it as open and useable as possible. As soon as new GVA or BRES data comes out, code from the repo can be re-run painlessly1. (Other datasets and linking will be added to this process.)

Other ways to get the data –>

  • Look in the data folder on the repo - there are separate subfolders for each group of data. Details for each of those are explained below.
  • Github has 4 options to access/download the files: download a single CSV, download the whole thing, get raw data (and its URL), copy to clipboard.
  • So e.g. after clicking on a CSV there are three small buttons in the top right that look like this:

  • Use ‘raw’ to get the URL for raw CSV data (to e.g. get directly from URL in code)

  • The rightmost button will download the CSV.

  • The middle button will copy the data to the clipboard.

  • To get ALL the data in one go: download (or clone) the entire repo. To download - see the green “CODE” button on the main page? Use that for the ‘download ZIP’ option, then look in the data folder after unzipping.
